# 扫描与修复项清单

本文件与代码一一对应（`netdoctor/scanner.py`、`netdoctor/fixids.py`、`netdoctor/fixers.py`）。
所有扫描项均为**只读探测**；只有标注了「自动修复」的项才会在用户确认后修改系统。

> 判定引擎（健康度 + 9 种故障形态 + 分形态处理预案 + 提示级归并）见
> [《体检判定与故障形态》](判定与故障形态.md)。

图例：严重度 `严重` > `高` > `中` > `低` > `提示`；「档位」中 `稳健` = 可逆免重启，`进阶` = 需二次确认且通常需重启。

---

## 一、连通性分层探针（判定"断在哪一层"）

| 顺序 | 探针 | 实现方式 | 判定 | 失败时结论（J 类） |
|---|---|---|---|---|
| 1 | 本机协议栈 | ping 127.0.0.1 | rc==0 | 协议栈本身异常 → 严重 |
| 2 | 默认网关 | ping 网关（可多个） | 任一通 | 内网不通：网线/路由器/交换机 → 高 |
| 3 | 公网 IP | ping 223.5.5.5 / 119.29.29.29 / 114.114.114.114 / 180.76.76.76 | 任一通 | 内网正常但出口异常（宽带/光猫/运营商）→ 高 |
| 4 | DNS 解析 | socket.getaddrinfo(baidu/qq/aliyun) | 任一成功 | DNS 问题 → 高 |
| 5 | DNS 服务器 | 逐个 ping 配置的 DNS | 任一通 | 配置的 DNS 不可达 → 高 |
| 6 | TCP 443 | socket 连接 域名:443 | 任一成功 | 端口被阻断（防火墙/安全软件）→ 高 |
| 7 | HTTP 访问 | urllib 请求（**显式绕过代理**） | 2xx/3xx 且有内容 | 应用层异常（代理/TLS）→ 中 |
| 8 | **浏览器路径** | 按注册表里的**系统代理**设置访问（`probe_via_system_proxy`） | 仅当配置了代理时才测 | 直连通、经代理不通 → **只有浏览器上不了网** → 高 |
| 9 | MTU 探测 | ping -f -l 1472 → 二分查找最大可用值 | ≥1300 | 分片黑洞 → 中 |

> 探针 1~7 为快速体检（`--quick`）所用；8、9 与 DNS 服务器逐项 ping 只在完整扫描中进行。
> 探针 6/7 在 `--fast` 模式下**仍会执行**——它们是区分「只剩浏览器上不去」与「全断」的关键依据。

## 二、A 类：链路层

| 编号 | 检查内容 | 判定条件 | 严重度 | 自动修复 | 修复动作 |
|---|---|---|---|---|---|
| `A.no-adapter` | 是否检测到物理网卡 | 无任何非环回网卡 | 严重 | — | 手动：检查驱动/硬件 |
| `A.all-down` | 所有网卡是否都未连接 | 无任何 up 网卡 | 严重 | ✅ | `fix.adapter.restart` |
| `A.disabled:<网卡>` | 网卡是否被禁用 | Status=Disabled | 高 | ✅ | `fix.adapter.restart` |
| `A.notpresent:<网卡>` | 设备记录存在但硬件不可见 | Status=Not Present | 提示 | — | 手动：设备管理器卸载隐藏设备 |
| `A.wifi:<网卡>` | 无线网卡是否已连接 | 无线且未 up | 中 | — | 手动：连接 Wi-Fi |
| `A.linkdown:<网卡>` | 有线链路是否连通 | 有线且未 up | 高 | — | 手动：检查网线/路由器端口 |
| `A.lowspeed:<网卡>` | 协商速率是否异常偏低 | 链路速率 ≤10 Mbps | 低 | — | 手动：换网线、改自动协商 |

## 三、B 类：IP 配置

| 编号 | 检查内容 | 判定条件 | 严重度 | 自动修复 | 修复动作 |
|---|---|---|---|---|---|
| `B.multi-adapter` | 多出口并存 | 活动网卡数 > 1 | 中 | — | 手动：禁用多余网卡 |
| `B.noip:<网卡>` | 是否有 IPv4 地址 | 无地址 | 高 | ✅ | `fix.dhcp.renew` |
| `B.apipa:<网卡>` | 是否拿到 169.254 自动私有地址 | IP 以 169.254. 开头 | 严重 | ✅ | `fix.dhcp.renew` |
| `B.zeroip:<网卡>` | IP 是否为 0.0.0.0 | IP == 0.0.0.0 | 高 | ✅ | `fix.dhcp.renew` |
| `B.nogw:<网卡>` | 是否有默认网关 | 网关为空 | 高 | ✅ | `fix.route.refresh` |
| `B.static:<网卡>` | 是否使用静态 IP | DHCP=Disabled 且有有效地址 | 低 | ✅ | `fix.dhcp.auto` |

## 四、C 类：DNS

| 编号 | 检查内容 | 判定条件 | 严重度 | 自动修复 | 修复动作 |
|---|---|---|---|---|---|
| `C.no-dns` | 是否配置了 DNS 服务器 | DNS 列表为空 | 高 | ✅ | `fix.dhcp.auto` |
| `C.hosts` | hosts 是否存在自定义记录 | 实测正常 → 提示；断网时：有效条目 ≥20 条 → 中；1~19 条 → 低 | 提示 / 中 / 低 | ✅ | `fix.hosts.restore` |

> hosts 条目不一定有害。若条目是你主动添加的（屏蔽广告、加速访问），可忽略该项。
> **实测能正常上网时，本项固定为「提示」级**：不压低健康度、不计入「需处理」、不自动勾选；
> 只有当前确实上不了网时，它才按上表的严重度作为嫌疑项参与判定。

## 五、D 类：协议栈

| 编号 | 检查内容 | 判定条件 | 严重度 | 自动修复 | 修复动作 |
|---|---|---|---|---|---|
| `D.local-stack` | TCP/IP 协议栈是否响应 | 127.0.0.1 ping 失败 | 严重 | ✅（进阶） | `fix.tcpip.reset` |
| `D.winsock` | Winsock 目录条目是否异常膨胀 | 条目数 ≥ 250 | 中 | ✅（进阶） | `fix.winsock.reset` |

## 六、E 类：代理 / VPN

| 编号 | 检查内容 | 判定条件 | 严重度 | 自动修复 | 修复动作 |
|---|---|---|---|---|---|
| `E.system-proxy` | 系统代理是否开启并指向地址 | ProxyEnable=1 且 ProxyServer 非空 | 高 | ✅ | `fix.proxy.disable` |
| `E.system-proxy-noserver` | 代理开关开启但无地址 | ProxyEnable=1 且地址为空 | 高 | ✅ | `fix.proxy.disable` |
| `E.pac` | 是否配置 PAC 自动配置脚本 | AutoConfigURL 非空 | 中 | ✅ | `fix.proxy.disable` |
| `E.env-proxy` | 是否存在代理环境变量 | 环境变量或注册表中存在 HTTP(S)_PROXY 等 | 中 | ✅ | `fix.proxy.env` |
| `E.winhttp` | WinHTTP 代理是否指向具体地址 | `netsh winhttp show proxy` 出现 IP:端口 | 中 | ✅ | `fix.proxy.disable` |
| `E.virtual-adapter` | 是否有虚拟网卡处于连接状态 | TAP/TUN/VPN/虚拟机网卡 up；若同时抢占默认路由则升级为高 | 高/中 | ✅ | `fix.route.refresh` |

## 七、F 类：系统服务

检查服务：`Dhcp`、`Dnscache`、`Netman`、`NlaSvc`、`nsi`、`netprofm`、`RpcSs`、`WlanSvc`（仅无线机型）、`MpsSvc`、`Winmgmt`。
查询方式：WMI `Win32_Service`（降级 `Get-Service`），不调用 `sc.exe`。

| 编号 | 检查内容 | 判定条件 | 严重度 | 自动修复 | 修复动作 |
|---|---|---|---|---|---|
| `F.disabled:<服务>` | 服务启动类型是否被禁用 | StartType=Disabled | 高（未运行）/ 中（仍运行） | ✅ | `fix.service.start` |
| `F.stopped:<服务>` | 常驻服务是否停止 | 属于 Dhcp/Dnscache/nsi/RpcSs 且未运行 | 严重（断网）/ 高（网络正常） | ✅ | `fix.service.start` |
| `F.stopped:<服务>` | 按需服务是否停止 | Netman/NlaSvc/netprofm/WlanSvc 未运行 | 中（仅在网络异常时提示） | ✅ | `fix.service.start` |

> 按需启动的服务停止本身不是故障。工具只在**网络已经异常**时提示，避免网络正常时报噪音。

## 八、G 类：路由

| 编号 | 检查内容 | 判定条件 | 严重度 | 自动修复 | 修复动作 |
|---|---|---|---|---|---|
| `G.no-default-route` | 是否缺少默认路由 | 无 0.0.0.0/0 路由且无网关 | 高 | ✅ | `fix.route.refresh` |
| `G.multi-default` | 是否存在多条默认路由 | 默认路由数 > 1 | 中 | ✅ | `fix.route.refresh` |
| `G.mtu` | 是否存在分片黑洞 | MTU 探测失败或最大 MTU ≤1300 | 中 | ✅ | `fix.mtu.reset` |

## 九、H 类：防火墙 / 安全软件

| 编号 | 检查内容 | 判定条件 | 严重度 | 自动修复 | 修复动作 |
|---|---|---|---|---|---|
| `H.block-outbound` | 出站策略是否整体阻断 | 出现 BlockOutbound / 阻止出站 | 高 | ✅（进阶） | `fix.firewall.reset` |
| `H.av` | 是否安装了第三方安全软件 | SecurityCenter2 有注册产品 | 提示 | — | 手动：临时退出网络防护验证 |
| `H.mpsvc` | 防火墙服务是否运行 | MpsSvc 未运行 | 低 | ✅ | `fix.service.start` |

## 十、I 类：系统环境

| 编号 | 检查内容 | 判定条件 | 严重度 | 自动修复 | 修复动作 |
|---|---|---|---|---|---|
| `I.time-skew` | 系统时间偏差是否过大 | 与 HTTP 服务器时间偏差 > 300 秒 | 中 | ✅ | `fix.time.sync` |
| `I.powersave` | 网卡是否启用节能断流 | AllowComputerToTurnOffDevice=Enabled | 低 | ✅ | `fix.powersave.off` |

> 时间偏差会导致 HTTPS 证书校验失败，表现为"所有网站都打不开"，极易被误判为断网。

## 十一、J 类：连通性结论

由分层探针结果自动推导，指出**断在哪一层**，并给出该层的处理路径：

| 首个失败层 | 结论文案 | 严重度 | 自动修复 |
|---|---|---|---|
| 本机协议栈 | 本机网络协议栈异常 | 严重 | `fix.tcpip.reset`（进阶） |
| 默认网关 | 内网不通：无法访问路由器/网关 | 高 | `fix.adapter.restart` |
| 公网 IP | 内网正常但无法访问外网（出口异常） | 高 | 手动（重启光猫/路由器，联系运营商） |
| DNS 解析 | 域名解析失败（DNS 问题） | 高 | `fix.dns.flush` |
| TCP 443 | HTTPS 端口被阻断 | 高 | 手动（检查安全软件/上网行为管理） |
| HTTP 访问 | 应用层访问异常 | 中 | `fix.proxy.disable` |

> J 类只描述「断在哪一层」。在此之上另有**判定引擎**，把分层结果收敛成一个
> 明确的健康度结论（健康 / 受限 / 全断）与 9 种故障形态，并按形态给出分别处理的
> 修复预案，见 [《体检判定与故障形态》](判定与故障形态.md)。

## 十二、修复动作全表

### 稳健档（默认勾选，可逆、无需重启）

| 动作 id | 名称 | 实际执行内容 |
|---|---|---|
| `fix.dns.flush` | 刷新 DNS 解析缓存 | `ipconfig /flushdns` |
| `fix.dns.register` | 重新注册 DNS 记录 | `ipconfig /registerdns` |
| `fix.dns.setpublic` | DNS 切换为公共 DNS | `netsh interface ipv4 set/add dnsservers`（默认不勾选） |
| `fix.dhcp.renew` | 重新获取 IP（DHCP 续租） | `ipconfig /release` + `/renew` |
| `fix.dhcp.auto` | 网卡切回自动获取 | `netsh interface ipv4 set address source=dhcp` + DNS source=dhcp |
| `fix.proxy.disable` | 关闭系统代理与 PAC | winreg 写 `ProxyEnable=0`、删 `AutoConfigURL` + `netsh winhttp reset proxy` |
| `fix.proxy.env` | 清理代理环境变量 | winreg 删除 HKCU/HKLM 的 HTTP(S)_PROXY / ALL_PROXY |
| `fix.hosts.restore` | 还原 hosts 文件 | 写回 Windows 默认 hosts（原文件已备份） |
| `fix.service.start` | 启动关键网络服务 | `Set-Service -StartupType Automatic` + `Start-Service` |
| `fix.adapter.restart` | 重启指定网卡 | `netsh interface set interface admin=disable/enable`（短暂断网 3~8 秒） |
| `fix.arp.flush` | 清空 ARP 缓存 | `netsh interface ip delete arpcache` |
| `fix.netbios.reset` | 重置 NetBIOS 名称缓存 | `nbtstat -R` |
| `fix.mtu.reset` | MTU 恢复 1500 | `netsh interface ipv4 set subinterface mtu=1500 store=persistent` |
| `fix.route.refresh` | 重建默认路由 | `route delete 0.0.0.0` + `ipconfig /renew` |
| `fix.powersave.off` | 关闭网卡节能断流 | `Set-NetAdapterPowerManagement -AllowComputerToTurnOffDevice Disabled` |
| `fix.time.sync` | 同步系统时间 | 配置 NTP 源 + 启动 w32time + `w32tm /resync /force` |

### 进阶档（默认不勾选，需二次确认，通常需重启）

| 动作 id | 名称 | 实际执行内容 | 影响 |
|---|---|---|---|
| `fix.winsock.reset` | 重置 Winsock 目录 | `netsh winsock reset` | 需重启；部分依赖 LSP 的软件需重装 |
| `fix.tcpip.reset` | 重置 TCP/IP 协议栈 | `netsh int ip reset` / `ipv4 reset` / `ipv6 reset` | 需重启；静态 IP、自定义路由会被清除 |
| `fix.firewall.reset` | 重置防火墙策略 | `netsh advfirewall reset` | 自定义防火墙规则全部清除 |

## 十三、备份内容清单

修复前自动落盘到 `backups/<时间戳>/`，并记录 `manifest.json`：

| 备份项 | 文件 | 是否可回滚 |
|---|---|---|
| hosts 文件 | `files/hosts_hosts` | ✅ 直接覆盖还原 |
| 系统代理设置 | `json/proxy_reg.json`（winreg 递归导出） | ✅ 按值写回 |
| WinHTTP 代理 | `text/winhttp_proxy.txt` | 参考快照 |
| IP 配置 | `text/ipconfig_all.txt` | 参考快照 |
| 路由表 | `text/route_print.txt` | 参考快照 |
| IPv4 整体配置 dump | `text/netsh_ipv4_dump.txt` | 可在紧急时用 `netsh -f` 整体还原 |
| DNS 配置 | `text/dns_servers.txt` | 参考快照 |
| 各接口 MTU | `text/mtu.txt` | 参考快照 |
| 服务启动类型与状态 | `json/services.json` | ✅ 逐服务还原启动类型 |
| 网卡电源管理 | `json/power.json` | 参考快照 |
| Winsock 目录（进阶时） | `text/winsock_catalog.txt` | 参考快照 |
| 防火墙配置（进阶时） | `text/firewall.txt` | 参考快照 |
